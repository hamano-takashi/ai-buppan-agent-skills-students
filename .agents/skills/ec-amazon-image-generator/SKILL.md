# Amazon Image Generator

## 画像生成の実行先

ChatGPT Images 2.5を画像生成・画像編集の標準対象とする。Codexでは利用可能な組み込み画像生成を使い、モデル名の入力を利用者に要求しない。内部モデルIDを選択・確認できない環境では、2.5やFlare/Sunburstへの固定・実行確認を断定しない。別方式は利用者の明示指定を優先する。 組み込み機能のためにAPIキーを要求せず、有料APIへ自動で切り替えない。実在商品は実物写真を基に編集する。

## 役割

Amazonの商品ページでCVR向上を狙う画像セットを設計し、画像生成AI・デザイナー・撮影担当へ渡せる制作指示に変換する。

品質基準は「商品説明だけの画像」ではなく、以下の購買導線を1セットで作ること。

1. トップ画像で検索・初見の興味を引く
2. 2枚目以降で悩み、機能、使用感、比較、サイズ、信頼を順に解消する
3. Aプラスやブランドストーリーで世界観と購入納得感を補強する

## 本リポジトリの必須制作ゲート（省略不可）

本スキルはAmazon向けの構成・制作指示を担当するが、ビジュアル制作の上位規約は次のとおり。

1. 着手前に `.agents/skills/ec-creative/references/masterprompt-protocol.md` を全文読み、全カットで制作チェック手順に沿った参考・構図・文字・固定要素の確認を行う。
2. 商品シート・人物シート・構図参考がある場合は `.agents/skills/ec-creative/references/composition-principles.md` も読み、各カットで主構図と補助視線誘導を宣言する
3. 参考画像を使う場合は `creative-reproduction-standard` で構造を抽出し、表層模写、固有コピー、ロゴ、特徴的意匠の流用を避ける
4. 実在商品はゼロから生成せず、ユーザー提供または案件内の実物写真マスターを基準に合成する。ロゴ、印字、形状、厚み、素材、色、同梱物を変えない
5. 日本語の長文、数値、バッジ、比較表はAI画像へ直接焼かず、HTML/CSS等の組版または後合成で配置する
6. 数値・実績・比較表現は `fact-check`、法令表現は `legal-check`、Amazon画像・A+の最新仕様は `platform-policy-check` で公式情報を当日確認する

これらのゲートと本スキルの記述が競合する場合は、上記ゲートとルート `AGENTS.md` を優先する。

## 最初に確認すること

ユーザーの依頼に不足がある場合でも、止まりすぎず「仮説」と明記して進める。ただし、規約・法務・薬機法・景表法に関わる表現は推測で確定しない。

最低限確認する情報:
- 商品名、カテゴリ、販売価格帯
- 商品の機能、素材、サイズ、同梱物
- ターゲット顧客、使用シーン、購入前の悩み
- 競合商品、差別化ポイント、訴求優先順位
- ブランドトーン、使用可能な写真素材、NG表現
- 作りたい成果物: メイン画像、サブ画像、Aプラス、ブランドストーリー、ブランドストア

## 実行ワークフロー

### Step 1: 入力を整理する

商品情報を以下に分解する。

- 顧客の購入前不安
- 競合と比べた選択理由
- 視覚化すべき機能・質感・サイズ
- 数値や実績など、証明できる根拠
- 規約・法務上あぶない表現

### Step 2: Amazon画像の役割を分ける

メイン画像とサブ画像を混同しない。

- メイン画像: 白背景、販売商品だけ、商品を大きく明瞭に見せる。テキスト、バッジ、装飾、生活背景は入れない。
- サブ画像: 使用シーン、ベネフィット、機能図解、比較、サイズ、同梱物、信頼要素で購入理由を積み上げる。
- Aプラス: ブランド世界観、比較表、詳細説明、利用シーンをモジュール単位で設計する。

詳細は必要に応じて `references/amazon-image-structure.md` を読む。

### Step 3: 7枚構成を作る

標準構成:

1. メイン画像
2. ベネフィット訴求画像
3. 機能・特徴画像
4. 使用シーン画像
5. 比較・証明画像
6. サイズ・同梱物・使い方画像
7. クロージング画像

商品ジャンルにより順番や枚数を調整する。ジャンル別の変換は `references/genre-patterns.md` を読む。

### Step 4: 画像生成プロンプトへ変換する

各画像ごとに、以下を必ず出力する。

- 画像番号
- 画像の目的
- ターゲット心理
- 画面構成
- メインコピー
- サブコピー
- 入れるべき視覚要素
- 入れてはいけない要素
- 画像生成プロンプト
- レタッチ・合成指示
- Amazon規約上の注意
- 品質チェック項目

プロンプト雛形は `references/prompt-templates.md` を読む。

### Step 5: 品質ゲートを通す

提出前に `references/quality-checklist.md` のチェックリストで自己レビューする。危険表現や素材不足があれば、完成物に混ぜず「確認事項」として分離する。

## 出力フォーマット

通常は以下の順で返す。

1. 前提・不足情報
2. 画像セット全体の戦略
3. 画像ごとの制作指示
4. 画像生成AIプロンプト
5. 法務・Amazon規約上の注意
6. 次に必要な素材・確認事項

## 制作原則

- 1枚1メッセージ。詰め込みすぎない。
- 商品写真を大きく、輪郭・質感・光沢を明確にする。
- スマホ表示で読めるコピー量に抑える。
- 機能語を顧客ベネフィットへ翻訳する。
- バッジ、丸ラベル、矢印、比較表、吹き出しで視線誘導を作る。
- 画像セット全体で色、フォント、余白、強調色を統一する。
- 根拠のないNo.1、最安、医療効果、永久保証などは使わない。
- 食品、美容、健康、医療、子供用品は表現リスクを明示する。
