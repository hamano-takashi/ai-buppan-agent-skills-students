# 執筆スタイルガイド（全題材共通・第1号で検証済み）

根拠: 売れ筋ビジネス書リサーチ（2026-08-02。木下勝寿著書=です・ます+一人称+フレームワーク名見出し+項目細分化 / KDP個人出版の売れ筋分量=1.5万〜2.5万字=商業出版の1/4 / 執筆は既存資産の再編集が出発点）。

## 文体
- です・ます調（敬体）・一人称「私」・言い切り（「〜と思われます」「〜かもしれません」原則禁止）
- 実務家本人が現場の台詞・実例から語る。序章の書き出しは「相談現場の一言」型が実績あり
- 絵文字・装飾記号・箇条書きの乱用禁止。本文は段落で語る（リストは真の列挙のみ）
- 説明の見せ方は本ごとのターゲット・方向性に合わせて代表と決める設計判断。
  参考: 第1号（未経験者向け実務書）では「ここで言葉を揃えておきます」等のメタな断り書き・脚注型定義文を
  使わず、説明を流れに溶かす方式を採用した（例=「クラウドファンディングは、まだ完成していない商品を
  専用ページで発表し、欲しい人が先に代金を払う予約販売です」と宣言せず直接語る）。
  新刊のP1目次段階で「説明の見せ方」をターゲットに合わせて確認する

## 見出し
- 章・節ともフレームワーク名または数字入りキャッチ型（例: 公開前9割の法則 / 達成率4割、実質2割）
- 「〜の分析」「〜について」等の機能説明型・説明的括弧書きは禁止

## 構成・分量
- 序章（1,500字前後）＋6章前後（各3,000〜3,500字・2〜3節）＋巻末。総量2.2万〜2.5万字
- 1節=1,200〜2,000字・1節1メッセージ（総量と節下限は数学的に両立しないことがある→総量優先で節を等分）
- 各章末「この章のまとめ」箇条書き3〜5行（本文の言い換えでなく持ち帰り事項）
- 次章予告は置かない（まとめが接続役）

## 必須ページ
- 巻頭「本書をお読みになる前に」（免責。テンプレ= legal-gate-checklist.md）
- 巻末: 実行チェックリスト（読者特典PDF連動）→出典・注記→著者について→最後に

## 数値・事例の扱い
- 外部データ=出典・時点・確認日を巻末「出典・注記」節へ。原稿中は【要fact-check: 〜】マーカーで管理
- 自社実務値=「私は〜を標準にしています」の体験表現＋免責ページでカバー
- 出典が存在しない数値は「私の体感では」に落とすか削除（「よく語られます」等の無出典引用風は不可）
- 数値例は必ず検算し「仮の数字です。自社の実績に置き換えてください」を明示
- 事例は匿名化必須。断片列挙でなく1事例を物語的に（媒体名等の公開情報は可）
- 実績数字は一次資料の有無を必ず確認（第1号の教訓: スキル記載のみの「250件」は代表判断で削除した）

## 図表
- 全体3〜6点。原稿には【図表: 内容説明】マーカーで指定し、EPUB組版時に画像差替
- グレースケールのみ（Kindle端末は白黒前提）・文字大きめ・線太め・仮の数字の注記を図内に

## 執筆の進め方（Rule 10準拠）
- 目次承認→序章+第1章で文体を代表と合わせる→残章を並列委譲（章ごとに: スタイルガイド+目次+
  既刊章=文体見本+担当章の素材+「書かないこと」境界を明示。KERNEL同梱・原稿にはS1-S4痕跡を入れない）
- 並列執筆後は必ず通し整合（章間の数値連動・重複記述・章参照）→推敲（マーカー件数のgrep前後一致・
  表記統一・章末まとめと本文のズレ）
