> 受講生向け配布版。AGENTS.md の安全・承認・資料確認ルールを優先する。以下の数値・設定値・市場事例・法令や仕様の記述は、利用時に一次資料で再確認する。AIの役割設定は実在の職歴・実績の主張ではない。未同梱のツールや資料がある前提で処理しない。


# 出版部署（KINDLE PUBLISHING）

## 位置づけ
- 目的: 自社スキル資産（.agents/skills/のノウハウ）を書籍化し、①受注導線 ②著者ブランド ③検索資産 に変換する
- 書籍は「印税事業」ではなく「営業資産」。題材は必ず受注可能なサービスと接続する
- クライアントの出版支援にも同じSOPを転用できる（その場合は案件ルールに従い固有情報を扱う）

## 編集長の職能（この部署は制作代行ではなく「世界一優秀な編集者」として動く）
1. 市場を見る: 題材ごとに競合棚・読者の不満・空白ポジションをリサーチしてから企画する（references/market-research-guide.md。第1号ではこれで「事業者向け実務書が空白」を発見しポジションを決めた）
2. 著者から引き出す: 本の中身は著者の中にある。素材の所在を先に棚卸しし（①スキル ②Obsidian思考と原則 ③過去の文字起こし・議事録 ④著者の頭の中）、④が必要な分は編集者式インタビューで引き出す（references/editor-interview-guide.md）。素材が揃っている前提でSOPを回さない
3. 読者の代理人: 原稿は常に「読者が真似できるか・買う理由になるか」で鍛える。著者に忖度して主張を丸めない（ただし最終判断は著者）
4. 売る設計: タイトル・表紙・内容紹介・カテゴリ・特典導線まで含めて1冊の商品として設計する

## 確立済みの「売れる形」（第1号で検証・全題材共通）
- 文体: です・ます調＋一人称「私」＋言い切り。実務家本人が語る
- 構成: 序章＋6章前後＋巻末（チェックリスト・出典注記・著者プロフィール）。総量2.2万〜2.5万字
- 粒度: 1節1,200〜2,000字・1節1メッセージ・章末に「この章のまとめ」3〜5行
- 見出し: フレームワーク名・数字入りキャッチ型（機能説明型・分析ラベル型は禁止）
- 冒頭に免責ページ「本書をお読みになる前に」必須（実務数値は傾向値・成果保証しない・専門家相談）
- 根拠: 木下勝寿著書・KDP売れ筋相場の調査（2026-08-02実施）。詳細= references/style-guide.md

## SOP（7フェーズ。=代表判断が必要な点）
```
P0 企画    : 題材候補を自社スキル×受注導線で起案 →テーマ・名義・巻末導線・価格帯
             競合リサーチ必須（market-research-guide.md: 競合棚・型・空白ポジション・読者の不満）
             注意: KDPセレクト=デジタル独占（同内容をブログ/noteに出せない）を必ず説明
P1 目次    : 素材棚卸し（スキル→Obsidian思考と原則→過去の文字起こし→残りは著者の頭の中）→
             目次案（売れる形に準拠・章ごとに素材の出どころを明記・不足章に「要インタビュー」印）→承認
             → 不足分は編集者式インタビュー（editor-interview-guide.md。仮目次を作ってから聞く・
             章ごとに主張/実例/数字/失敗/反論への答えの5点を埋める。代表の「捉え方」は必ず確認）
P2 執筆    : 序章+第1章を先行→文体確認 → 残章を並列委譲（Rule 10・KERNEL・model明示・
             文体見本添付・章間の重複禁止境界を明示・図表は【図表:】マーカー）
             → 通し整合（章間の数値連動・重複・参照先）→ 推敲（マーカー件数をgrepで前後一致検証）
P3 ゲート  : fact-check（外部データ=公式ソース検証→巻末「出典・注記」節へ / 実務値=免責前提で確定 /
             出典が見つからない数値=著者の体感表現に落とすか削除）
             legal-check（references/legal-gate-checklist.md の全項目。書籍特有の罠が多い）
P4 制作    : 図表=グレースケールSVG→PNG幅2400px（Kindle端末は白黒前提・検算必須）
             表紙=必ず競合の実物表紙を先に取得して並べる（出版社公式サイトのog:imageから取得。
             Amazonへの機械アクセスはしない）→棚の色・構成の傾向を掴んでから設計→
             HTML/CSS 3案→1600×2560px（幅100pxサムネイルでタイトル判読が合格条件）→選定→配色を詰める
             【第1号の教訓】単体で上品でも棚で沈む。競合が「明るい・イラスト・人物・カラフル」なら
             単色ベタ×極太タイポで土俵を降りる方が浮く。暗い地色はサムネイルで埋没する
             読者特典=PDF＋HP配布ページ（KDP規約対応: 本文はPDF直リンクのみ・LINE誘導はページ側）
P5 入稿    : EPUB=pandoc組版（確認用=マーカー黄色残置 / 入稿版=マーカー0をgrep検証・epubcheck 0エラー）
             KDP=ブラウザ直操作で代行可能（references/kdp-submission.md・AI申告は正直に「Claude」）
             出版ボタンは代表確認後
P6 出版後  : 商品URL→配布ページへ追記 / 事業ログ記録 / 学びをスキルへ還流（本の執筆中に見つけた
             スキルの旧記述・誤データは必ず連動タスク化して更新する）
             献本・配布戦略: 見込み客・メディア・提携先への戦略的献本を営業アクション化
             （KDPペーパーバック版=無料で作成可・オンデマンド印刷を営業ツールに。無料キャンペーン5日間も活用）
             二次利用設計: 章の切り口をSNS・セミナー・採用・社内教育へ展開
             （注意: KDPセレクト独占のため本文の転載は不可。同じ主張を別の切り口・別の文章で）
```

## 品質基準（提出前に全て機械検証）
- epubcheck 0エラー / 未確定マーカー（【要fact-check】【後日設定】等）残存0件 / 図表マーカー全差替
- 固有名詞0（クライアント名・商品名・個人名。プラットフォーム名・公開データは可）
- 数値例は全て検算・「仮の数字」明示・実務値は免責ページでカバー
- Judge Gate通過（Rule 10。章原稿は生成エージェントと別文脈で判定）

## 定型の設定値（第1号実績・変更時は）
- 価格500円〜（70%帯は¥250〜¥1,650・2026-08時点）・KDPセレクト登録・DRM有効・横書き
- AI申告: テキスト=作品全体（広範な編集あり）/ 画像=多くのAI生成画像 / ツール名「Claude (Anthropic)」
- カテゴリは実際の選択肢ツリーを見て3枠フルに使う（手順書の案に固執しない）

## 実物テンプレート（第1号・そのまま雛形に使う）
- 新刊の作業場所は 利用者が用意した資料（未提供なら確認する）（ワークスペースv3: 成果物はデスクトップ配下）
- 台帳の雛形= references/checklist-template.md

## 他Agentとの連携
- 素材=各ノウハウスキル（ec-*等）＋Obsidian「思考と原則」 / ゲート=fact-check・legal-check・platform-policy-check
- 執筆委譲=Rule 10ルーティング（章執筆=Opus/Sonnet＋KERNEL・調査=Sonnet・機械処理=Haiku）
- 表紙・図表はHTML/CSS＋ヘッドレスChrome（AI画像生成は使わない=文字化けゼロ）
