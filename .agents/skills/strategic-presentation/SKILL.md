# 意思決定できる提案資料

利用者が確認した課題、実際の商品・サービス、利用権限のある一次資料から始める。講師の実績や過去案件の数字を持ち込まない。

## 構成

1. 今回決めてほしいことを一文で示す。
2. ヒアリングで確認した現状と問題を、期間・件数・原本とともに説明する。
3. 問題が生じる構造を分解し、事実と仮説を分ける。
4. 現状維持、予算を抑える案、成果に必要な範囲を含む案を比較する。
5. 実行範囲、費用、役割、期限、検証条件を示す。
6. 回収の前提、向いていないケース、意思決定者の主な懸念への対応を示す。

一枚につき判断に必要な主張を絞る。実物画面、商品写真、作業の流れ、数値の図解は、権限を確認した素材で用意する。見栄えだけの装飾や、存在しない実績の見本画面を作らない。

## 架空の計算例

以下は計算方法だけを示す架空例であり、実績や効果保証ではない。

- 対象訪問数: 月10,000件。
- 購入率の仮説: 2.0%から2.5%。
- 追加注文の試算: 10,000 × (0.025 − 0.020) = 50件/月。
- 追加費用控除後の利益: 1注文あたり1,000円。
- 追加利益の試算: 50 × 1,000 = 50,000円/月。
- 初期費用100,000円の場合の単純回収期間: 100,000 ÷ 50,000 = 2か月。

流入数、利益単価、改善が維持されるという仮説が必要。立ち上がり、季節性、継続費用、返品を別途確認する。複数施策の追加注文を同じ母数へ二重加算しない。

## 提出前

課題がヒアリング内容か、主張に根拠があるか、代替案と費用が比較できるか、担当と期限が明確か、反論に答えているか、読んで判断できるかを確認する。

実ファイルを作ったときは全ページを表示して文字切れ・図の誤り・数値を確認する。資料作成ツールが未接続なら、利用可能な正規の機能を確認し、できる形式で納品する。無承認で外部サービスへ原稿を送信しない。
