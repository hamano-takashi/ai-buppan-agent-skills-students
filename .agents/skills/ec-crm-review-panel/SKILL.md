# CRM配信物の確認

審査役は最終文を書かず、指摘と根拠を返す。利用者の依頼、文体、禁止表現、確認済みの事実を先に読む。元の原稿はローカルに残す。

## 四つの確認視点

1. 顧客: 誰のどの場面に役立つか。期待する行動が明確か。関係のない煽りや押し付けがないか。
2. 文章: 内容の順序、具体性、読みやすさ、必要情報、文体が目的に合うか。
3. 事実と表示: 日付・価格・実績・商品属性の根拠があるか。複数商品にまとめて断定していないか。限定の理由が実在するか。
4. 同意と運用: 同意取得、解除、リンク、宛先、セグメント、配信時刻、重複配信を確認できるか。

法令は legal-check、媒体規定は platform-policy-check、事実は fact-check の現時点の確認を使う。参照の基準表は [brand-rules-template](references/brand-rules-template.md)、[checklists](references/checklists.md)、[reviewer-personas](references/reviewer-personas.md) を必要に応じて読む。基準表の数値や著者の体験を当該事業の実績にしない。

## 審査結果

対象箇所、指摘理由、根拠、重要度、追加確認を返す。重大な誤り・未確認の対外主張・同意や規約違反がある場合は配信不可とする。
修正は生成役へ戻し、文章全体のつながりを確認してから再審査する。利用者の希望する長さを尊重し、不要な長文化や短文化を強制しない。

独立したAIが使えるときは審査を分ける。使えないときは役割切替で点検し、独立レビュー済みとは言わない。配信自体は利用者の明示承認後に行う。
改善の検証には配信件数、クリック件数、購入件数、解除件数など管理画面で取得できる指標を使い、定義と分母を確認する。外部の差し戻し率を初期値にせず、自分の実測から基準を作る。
