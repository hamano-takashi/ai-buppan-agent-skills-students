# C/Pバランス商品設計

## 目的

商品を「最初に買われる力」と「買った後に支持される力」に分け、片方だけを最適化する失敗を防ぐ。
新商品企画ではCとPの検証をローンチ前の必須ゲートにし、発売後はトライアルとリピートを分けて診断する。

詳細な理論・出典・動画確認メモが必要なら `references/theory-and-evidence.md` を読む。
実務で診断票を作る場合は `references/diagnostic-template.md` を使う。

## 基本定義

- C（Concept）: 購入前に「欲しい」と思わせる力。誰のどんな生活上の課題を、何によって、どう変えるかという約束。
- P（Performance）: 購入後に「買ってよかった」と思わせる力。約束した便益を実際の品質・使用体験・サービスで実現する能力。
- C/Pバランス: CとPを平均して帳尻を合わせることではない。両方が対象顧客の合格水準を超える状態。

「C/P＝コストパフォーマンス」と解釈しない。広告・コピーはCの伝達手段であり、Cそのものの代替ではない。

## 必須原則

1. CとPを別の時点・別の質問で測る。購入前意向をPの証拠にせず、購入後満足をCの証拠にしない。
2. Cの改善でPの不足を隠さない。Pが弱い商品への集客増は、失望・返品・低評価を拡大する。
3. Pの高さだけで発売を決めない。Cが弱ければ、良さを体験する最初の購入者が増えない。
4. 万能の合格率を置かない。カテゴリー、価格、購買頻度、既存商品のベースラインを先に定める。
5. 率には分子・分母・期間・対象を併記し、絶対数でも示す。データがなければ0で埋めず「未取得」とする。
6. 成功率、No.1、効果、性能などの数値主張は原典を確認する。確認できなければ「要ファクトチェック」とする。

## 実行フロー

### Step 1: 課題と成功条件を再定義する

次を先に明示する。

- 対象商品・カテゴリー・価格・チャネル・対象顧客
- 判断目的: 新規企画、試作品評価、発売可否、既存商品の改善のいずれか
- 成功条件: C、P、事業性を何と比較して合格とするか
- 欠落データ: 購入前評価、使用後評価、トライアル数、再購入数、返品・苦情など

欠落を推測で埋めない。仮説を置く場合は、取得方法と判定時期を付ける。

### Step 2: 顧客ニーズと約束を構造化する

顧客の言葉をそのまま商品案にせず、最低3段のWhy So?で生活上の課題まで掘る。

```text
欲しい商品（Have）
  <- なぜ欲しいか
行いたいこと・解決したい生活上の問題（Do）
  <- なぜそれが重要か
なりたい状態（Be）
```

商品コンセプトを一文で固定する。

```text
[対象顧客]が、[未充足の生活上の課題]を、[商品アイデア]によって解決し、
[購入後に実感できる便益]を得られる[カテゴリー名]。
```

新市場創造を狙う場合のみ、講義で示された `C = I + NCN + B` も使う。

- I: 商品アイデア。企業が技術・原価を投入して実現する対象であり、Pの中核になる。
- NCN: 新カテゴリー名。顧客が何として理解するかを決める。
- B: 未充足の強いDoニーズに応える便益。

既存商品の改良では新カテゴリー名を無理に作らない。C/P診断とMIP判定を混同しない。

### Step 3: Cを購入前に検証する

完成品の使用経験がない対象者に、統一したコンセプト刺激を提示して測る。

- 欲しさ・購入意向
- 自分との関連性、解決したい課題との一致
- 独自性とカテゴリー理解
- 便益の明確さ・信頼性
- 価格を含めた受容性

広告CTRや商品ページCVRはCの補助指標であり、ターゲティング、価格、配荷、クリエイティブの影響を分離する。

### Step 4: Pを購入後に検証する

対象顧客に、便益を判断できる十分な期間・条件で試作品または実商品を使用してもらう。

- 約束した便益が実現した人数
- 総合満足、継続利用意向、再購入意向
- 実際の再購入者数・推奨者数
- 返品数、苦情数、低評価理由
- 使いにくさ、品質ばらつき、期待との差

再購入意向と実購入を区別する。耐久財など再購入が遅い商品では、継続使用・推奨・関連商品購入を代替指標として定義する。

### Step 5: 4象限で診断する

| C | P | 型 | 売上の構造 | 優先対応 |
|---|---|---|---|---|
| 高 | 高 | 成功商品型 | トライアルもリピートも生まれる | 供給・認知を拡大し、Pを監視する |
| 高 | 低 | 線香花火型 | 初動は出るが、再購入が続かない | 集客拡大を止め、Pを改良する |
| 低 | 高 | スロースタート型 | 使用者は支持するが、新規購入が増えにくい | C、カテゴリー理解、伝達を再設計する |
| 低 | 低 | 空振り型 | トライアルもリピートも弱い | 小修正で延命せず、ニーズから再設計する |

高低は感覚で決めない。同じ対象顧客・条件で測った基準値、既存商品、競合または事前に定めたGo基準と比較する。

### Step 6: 3案以上を比較して打ち手を選ぶ

最低でも次の3レベルを比較する。

1. 伝達修正: 表現、カテゴリー名、パッケージ、商品ページを変える。
2. コンセプト修正: 対象顧客、未充足ニーズ、便益、価格の組み合わせを変える。
3. パフォーマンス修正: 仕様、品質、使用体験、付帯サービスを変える。

期待効果、リスク、コスト、難易度、再検証方法を同じ表で比較する。Cが弱い原因を広告不足、Pが弱い原因を認知不足と短絡しない。

### Step 7: Go / Revise / Stopを判定する

- Go: CとPがともに事前基準を満たし、事業性・安全性・供給面にも重大な未解決がない。
- Revise: 片方が未達だが、原因と修正仮説を特定でき、再検証可能。
- Stop: 両方が未達、根拠データが取得不能、または安全・法務上の重大な問題がある。
- Hold: Pをまだ測れる試作品・使用期間がなく、判断材料が不足している。

P未検証を「仮の高評価」としてGoにしない。Fail ClosedでHoldにする。

## 出力形式

```text
結論: Go / Revise / Stop / Hold

1. 課題・成功条件・制約・欠落データ
2. ニーズ構造: Have <- Do <- Be
3. C評価: 根拠、分子/分母、判定
4. P評価: 根拠、分子/分母、判定
5. 4象限診断とWhy So? 3段
6. 改善3案比較: 効果 / リスク / コスト / 難易度 / 検証
7. 選定案とトレードオフ
8. 今日の一歩
9. 検証計画: 絶対数、測定時期、判定者
10. 要ファクトチェック事項
11. 6軸自己採点
```

提出前にCとPの証拠が混ざっていないか、同じ母数を二重計上していないかを検算する。

## 他スキルとの境界

- `cpo`: 商品戦略、ロードマップ、PMF全体を統括する。C/Pは商品力の判定ゲートを担当する。
- `ec-brand-strategy`: KBF・KSFとブランドの成功状態を定義する。C/Pは個別商品の購入前後評価を担当する。
- `ec-launch-workflow`: 発売実行を統括する。C/PのGo判定前に集客フェーズへ進めない。
- `ec-acquisition` / `ec-creative`: Cの伝達を最適化する。Pの不足を広告・表現で補わない。
- `ec-engagement` / `ec-insight`: 購入後データを取得し、Pと再購入を検証する。
- `fact-check` / `legal-check`: 数値・No.1・効果効能・広告表現を公開前に確認する。
