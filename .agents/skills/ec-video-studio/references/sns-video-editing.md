# SNS動画編集パイプライン（Claude Code全自動編集）

撮影済み素材（解説動画・商品動画・対談等）をClaude Code＋ffmpegで
プロ品質に自動編集する手順。編集ソフトは開かない。
出典: @masahirochaen 2026-07-04実証（13分解説動画をClaude Codeが全編集）＋当社SNS動画知見。

## 実証された全自動編集の範囲

素材mp4を渡して「編集して」だけで以下が完結する:
1. 無音・噛み・言い直しのジャンプカット
2. テロップ・章タイトル・強調テロップの焼き込み
3. 効果音・BGM・ロゴ・B-roll挿入
4. サムネイル3案の生成

## 標準パイプライン（7ステップ）

1. 解析: `ffprobe` で尺・解像度・音声情報を取得。`whisper`（ローカル）で
   タイムスタンプ付き文字起こし（`--output_format json`）
2. カット設計: 文字起こしから (a)無音区間（例: 0.6秒以上） (b)噛み・言い直し
   （同語句の反復）(c)フィラー（「えー」「あの」）を検出し、カットリストを作る。
   カット点は音素の切れ目に置く（語中で切らない）
3. ジャンプカット実行: ffmpegで区間を切り出し concat。
   映像は `-c:v libx264 -crf 18` 以上、音声はクロスフェード（プツ音防止）
4. テロップ焼き込み: ASS字幕（`libass`）で全編字幕＋強調テロップ＋章タイトル。
   フォント・色・縁取りはブランド指定に従う（未指定時: 白文字・黒縁・下部中央）
5. 音: BGM（-18〜-14 LUFS目安、声より-10dB下）、SE（場面転換・強調に音ハメ）、
   冒頭/末尾フェード。ラウドネス正規化 `loudnorm`
6. ブランド要素: ロゴ（隅に常時 or 冒頭のみ）、B-roll（説明区間に挿入）、
   2段CTA（中盤軽く＋末尾本命）
7. サムネイル: 表情の良いフレーム抽出＋タイトル文字焼き込みで3案生成

## SNS動画の勝ちパターン（2026年基準・制作前に必ず適用）

- フックは0〜3秒: 結論・ベネフィット・違和感を最初に。挨拶から始めない
- 1.5〜3秒間隔のジャンプカットでテンポを作る（間延び=離脱）
- キネティック字幕（動き・強調色のあるテロップ）で無音視聴に対応
- SEの音ハメ: カット・図解出現に効果音を同期
- 9:16縦が基本（YouTube長尺は16:9、Amazon掲載動画は16:9のみ）
- 2段CTA: 中盤にさりげなく＋末尾に本命
- ムックバン素材等の「羅列」はNG。必ずストーリー（フック→展開→CTA）に組む

## 提出前の自己QC（MANDATORY・ユーザーにチェックさせない）

全編を通しで自分で確認してから提出する:

| # | チェック | 方法 |
|---|---|---|
| 1 | 全編描画 | 全編再生またはシーン毎フレーム抽出で黒画面・崩れがないか |
| 2 | 音声切れ | カット点で語尾が切れていないか（カット±0.3秒を聴取/波形確認） |
| 3 | 間延び | 3秒以上変化のない区間が残っていないか |
| 4 | テロップ | 誤字・タイミングずれ・見切れ（セーフエリア内か） |
| 5 | トランジション | 不自然なジャンプ・フラッシュがないか |
| 6 | 音量 | 声/BGM/SEのバランス、ラウドネス正規化済みか |
| 7 | コンプラ | ステマ・景表法・プラットフォーム規約（Amazon動画は食レポ字幕転用等に注意） |

- 描画確認はクロップ静止画でも行う（注ぎの向き・水流・左右反転など物理整合を含む）
- 「たぶん大丈夫」で出さない。1つでも未確認なら提出しない（Verification Before Done）

## 編集手段の選択（palmier-pro分岐）

1. AIネイティブ動画編集MCP palmier-pro（PalmierPro.app / localhost:19789）が使える環境なら優先:
   アプリを起動→`/mcp`で再接続→編集操作をMCP経由で実行（タイムライン編集・テロップ・
   トランジションがGUI品質で扱える）
2. palmier-proが無い/起動しない環境では本ファイルの ffmpegパイプラインで完結させる
   （品質要件は同一。quality-gates.mdのQCも同一）
3. どちらの場合も自己QC（上記「提出前の自己QC」）とコンプラチェックは省略しない

## 実行時の注意

- whisperはローカルCLI（無料）を使う。外部APIに音声を送らない（機密・コスト）
- 素材・中間ファイルは案件ディレクトリ内 `work/` に置き、完成品と分離
- 長尺（10分超）は章単位で処理し、最後に結合（メモリ・やり直しコスト対策）
- フォントは商用利用可のものだけ使う（源ノ角ゴシック/Noto系が安全）
