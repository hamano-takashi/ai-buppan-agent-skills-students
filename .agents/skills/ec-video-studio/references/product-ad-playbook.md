# 商品広告動画プレイブック（EC広告・CM・LP/商品ページ用動画）

実在商品を扱う広告動画に特有の手順。ストーリー構造は short-drama-playbook.md、
生成技術は higgsfield-production-pipeline.md、人物は character-consistency.md を継承し、
本ファイルは「商品の忠実再現」と「広告フォーマット」の差分を定義する。

## 大原則: 商品は「生成」しない、「合成・編集」する

AIは実在商品のパッケージ・ラベル文字・ロゴ・形状比率を正確に再現できない（文字化け・崩れ）。
商品が主役の広告で商品が実物と違うのは、品質以前に事故である。

商品カットの作り方（優先順）:
1. 実物のクリーンな商品写真（白背景・高解像度・複数角度）を必ず入手する。
   無ければ制作を始める前に撮影を依頼する（過去の教訓: クリーンなパッケージカットが
   無いまま進めると、後工程がすべて繕い作業になる）
2. `remove_background` で切り抜き→AI生成した背景・シーンに合成する
3. または画像編集系モデル（Nano Banana Pro等）に実物写真を渡し、same product構文で編集:
   ```
   Edit the scene from the reference image: keep the exact same product
   (same package, same label text, same logo, same proportions, same colors),
   and change only the background to [シーンの詳細].
   ```
   ※チュートリアルの「ロゴ入りヘッドホン」工程と同じブランド要素忠実合成の技術
4. 生成後、ラベル文字・ロゴ・形状をクロップで実物写真と突合。1文字でも違えば不採用

## 商品忠実性チェック（QC10軸の軸1を商品版として適用）

| # | チェック | 判定方法 |
|---|---|---|
| 1 | ラベル・ロゴの文字 | クロップ画像を実物と1文字ずつ突合（完全一致のみ合格） |
| 2 | 形状・比率・色 | 実物写真と並べて比較。ブランドカラーは色コード照合 |
| 3 | 使用シーンの物理整合 | 持ち方・注ぎの向き・水流の起点終点・左右・内容量感を拡大静止画で確認 |
| 4 | 機能表現の実使用適合 | 演出が商品の実際の使い方に合っているか（例: 粉末飲料の常套句を機械流用しない） |

## 演出の禁止事項（プロダクト表現・MANDATORY）

- 装飾エフェクト禁止: 光輪・粒子・浮遊・キラキラ等。演出は「機能の可視化」のみ
  （クリーン背景のクローズアップ、内部構造CG、検証映像風の実演）
- AI感のある人物・商品は不採用（quality-gates.md 実写度アンカー適用）
- 効果の誇張表現・体感の断定は fact-check / legal-check を通るものだけ

## 広告フォーマット6型（配信目的で選ぶ）

| 型 | 構造（15〜30秒配分） | 向き | 法規・注意 |
|---|---|---|---|
| 問題解決型 | 悩みシーン(0-5s)→商品登場(5-10s)→解決デモ(10-25s)→CTA | 定番・CV目的 | 効果表現はfact-check |
| デモ・機能可視化型 | 機能クローズアップ連打→内部構造→結果 | 機能に差がある商品 | 装飾エフェクト禁止・実演のみ |
| UGC体験談風 | 自撮り風フック→使用感→推し→CTA | SNS面・信頼獲得 | 「広告」表記必須（ステマ規制）。架空人物の体験談化は不可。適法パターン=実在顧客のVOC・レビューを本人許諾＋広告表記つきで引用し、AI人物には「イメージ・再現映像」表記 |
| ドラマ型 | short-drama-playbook.md の商品ドラマ化表 | ブランド・認知 | 商品は「転機」の位置に |
| ビフォーアフター型 | Before→経過→After | 美容・健康系 | 薬機法・景表法・媒体ポリシー制限が最も厳しい。platform-policy-check必須 |
| 比較型 | 従来の不便→自社の差分 | 指名検索対策 | 客観的根拠必須・他社誹謗NG |

- 迷ったら: CV目的=問題解決型 / 認知目的=ドラマ型 / SNS運用=UGC風＋デモ型の2本立て
- どの型でもフック0-3秒（痛みのシーン or 意外な使用結果から入る。商品ロゴから入らない）

## プレミアムD2C構成テンプレ3種（MYTREX実測・quality-gates.md広告クラフト7基準とセットで使う）

| テンプレ | 構成（30秒≒12カット/20秒≒8カット） | 対応する6型 |
|---|---|---|
| 機能デモ型 | フック（人物 or コピー）→技術/特徴名の大型タイポ→実写手元マクロ→数値図解（矢印・単位）→ユースケース連打（カラーブロック色分け＋数値対応）→緩急カット→タグライン | デモ・機能可視化型 |
| VOC型 | 白背景コピー1本の静フック→VOC連打（属性ラベル常設＋「※個人の感想です」脚注）→機能可視化（内部CG/マクロ）→製品ヒーロー＋ブランド想起 | UGC体験談風（実在VOC・許諾つき） |
| データフック型 | 数字フック0-2.5秒（グラフアニメ＋悩み仕草を顔なしで＋出典脚注）→機能可視化→製品名ヒーロー→生活シーン+VOC字幕→使用デモ→ラスト3カット製品ヒーロー固定 | 問題解決型 |

- 食品への翻訳: 内部CG↔シズル物理（溶解マクロ/注ぎスロー/湯気/氷の結露）、mm図解↔分量・杯数・手順秒数、部位別色分け↔飲み方バリエーション色分け
- 人物の3役: 悩みの仕草（顔なし=自分ごと化）/ VOC語り（属性ラベル）/ 使用シーン。1本の中で役割を分ける

## 感情起点の設計（制作前に必ず・30分）

1. 支配感情の特定: 顧客が購買時に最も強く抱く感情1つを言語化（ec-drm references参照）
2. 感情ベネフィット2軸: 機能ベネフィット→感情ベネフィットに翻訳してからコピー化
3. 訴求点はPOXで選ぶ: 競合のPOF（欠点）→ニーズ検証→自社POD（独自差分）を動画の核に
4. VOC（顧客の声）があれば「買う理由」のズレを検出してから台本化（ec-lpo作成層と連携）

## 配信面別仕様（確定前に platform-policy-check・確認日付き）

| 配信面 | 規格の目安 | 設計上の注意 |
|---|---|---|
| Meta/TikTok/リール広告 | 9:16・15〜30秒 | 無音再生前提=字幕で完結。2段CTA |
| Amazon（商品ページ/SB動画） | 16:9のみ | 食レポ字幕の広告転用等はステマ/景表リスク。規格・審査要件を都度確認 |
| LP/ECサイト埋め込み | 16:9 or 1:1・30〜60秒 | 自動再生ミュート前提=冒頭から字幕。ループ設計 |
| YouTube広告 | 16:9・6秒/15秒/30秒 | 5秒スキップ前提=最初の5秒に核心 |

## Mode C 制作パイプライン（共通パイプラインとの差分）

1. 要件定義に追加: 目的（認知/CV）・配信面・POXに基づく訴求点1つ（欲張らない）
2. 感情設計→フォーマット選定→カット表（1カット=1メッセージ・台本テキスト）
2.5. 絵コンテ＝画像ボード（SKILL.md共通パイプライン5・スキップ禁止）: 全カットのキーフレームを
   画像で並べたボードを作りユーザー確認を取ってから動画化する。実写流用カットは実フレーム抽出、
   新規AIカットはCodex組み込み画像生成（標準対象=Images 2.5・利用枠に従う）で複数パターン生成→ユーザー採用→採用画像を
   image-to-videoのstart_imageに使う（Higgsfieldクレジットは動画化のみに使う）
3. 商品マスター画像の確定（実物写真）→ 商品固定プロトコル（本ファイル冒頭）。
   ※未公開商品の写真は案件固有情報。外部（Higgsfield等）へ渡す前にSKILL.mdの
   外部送信ゲート（GWチェック＋毎回ユーザー事前承認）を必ず適用
4. 人物が出る場合はキャラ固定（character-consistency.md）。手元だけのカットは破綻リスク低で優先
5. 生成→編集→QC10軸＋商品忠実性チェック4項目
6. 必須ゲート: fact-check（効果・数値・No.1）＋legal-check（景表法・薬機法・ステマ）＋
   platform-policy-check（配信面仕様）
7. Judge Gate→ユーザー承認→納品（検証成果物一式を添付）
