## 核心思想（現場運用 5原則）

```
1. キャンペーン構造が全ての始まり
   - 命名規則が崩れたアカウントは集計不能・分析不能
   - メンテの優先順位付けはまず構造から

2. 広告費降順がメンテの鉄則
   - 触るべきは「広告費を多く使っているところ」から
   - 1個1個全部触ると切りがない・インパクト最大化

3. 「悪かったら止める」は素人判断
   - CPC下げて維持が正解・止めるのは最終手段
   - 大きなKWを簡単に止めるアカウントは即診断対象

4. SEOと広告は分離して考えない（広告は自然検索売上の"絶対値"を上げる投資）
   - 広告は「SEOへの投資」。Amazon検索順位の第一ロジック＝直近1ヶ月の販売個数（オーガニック/広告どちらでもよい）
   - 広告未設定はSEOで不利になる（広告を設定しただけで自然検索が上がる事例多数）
   - 支援平均で売上の4〜5割が広告経由。これを自然検索売上の絶対額を伸ばして"依存度"を下げる（自然検索比率を高めるのが最終ゴール）
   - 比率（TACoS）が低すぎる＝広告を使わなさすぎ＝機会損失。率でなく絶対値で判断する

5. クライアントコミュニケーションが半分
   - 数字改善と同じくらい「存在感の演出」が重要
   - データ見たらスクショ＋コメントを残す
```

## 能動診断プロトコル（数字を見たら先回りで動く・MANDATORY）
> 現場のベテランは「聞かれてから」動かない。数字を一目見た瞬間に「ここ確認しましょう、たぶん原因はこれ、こう触ります」と先回りで出す。受け身は素人運用。指標・症状・Benchmarksの話題が出たら質問の有無に関わらず起動する。

### 出力の型（4段・固定）
```
シグナル（観測した数値・状況）
 → 確認する画面（広告コンソール/ビジネスレポート/検索語句レポートのどこを見るか）
 → 現場の見立て（想定原因）
 → 触り方（具体的な入札/構造/ページの打ち手）
```
- 絶対値で慌てない。 対カテゴリ平均（Benchmarks）・対市場・前回比で「高い/低い」を言う。
- 「悪かったら止める」に直行しない（核心思想3）。CPC下げて維持が基本、止めは最終手段。

### 現場の検知→打ち手 早見表
| シグナル | 確認する画面 | 現場の見立て | 触り方 |
|---|---|---|---|
| CTRがカテゴリ平均以下 | SERPでメイン画像/タイトル冒頭/価格/星を競合と並べる | 枠内で選ばれていない（入札の問題ではない） | 画像・タイトル冒頭・価格を直す。入札は上げない（上げても消耗） |
| CTR高いのにCVR低い | 詳細ページ（A+/レビュー/価格）＋検索語句レポート | クリックは取れるがページが売り切れない／無関係語にクリック流出 | A+/サブ画像/価格を改善＋負け語をネガティブKW |
| CPCがカテゴリ平均超で高騰 | Top of Search IS とROAS、ヘッドKWの順位 | 指名級ヘッドに過入札 | 通常20-30円、大胆50-60円で調整。グッと下げは3/4〜半分。ロングテール昇格へ寄せる（核心思想3） |
| CPM高い（SB/SD/DSP） | オーディエンス定義・配置面 | 面が広い／プレミアム面で競合 | オーディエンス・配置を絞る |
| NTB率がフェーズと不一致 | フェーズ（新規 or 既存深耕）＋TACoS推移 | 成長期で低い＝指名偏重／成熟期で高い＝新規に払い過ぎ | SP指名/非指名・SB/SDの配分を組み替え |
| 完視聴率が平均以下 | 冒頭3秒・配置面・縦横比 | フックが弱い | 冒頭3秒を作り直す（ec-creative連携） |
| 在庫WoC 4週未満 | 在庫レポート・需要予測 | 在庫切れ前夜＝広告の無駄打ちリスク | 広告にブレーキ、補充優先（在庫切れはSEO順位も毀損） |
| 指名（ブランド）KWに出稿していない | 検索語句レポート＋SERPで自社指名KWの広告枠 | 競合が指名KWを奪取＝1クリック級の機会損失 | 指名KWを即入稿（守りで必須）。事例で月商70万→200〜300万（Skill 25） |
| TACoSが商材レンジより低い | アカウント全体売上に対する広告費比率＋自然検索売上の絶対額 | 広告を使わなさすぎ＝自然検索を伸ばす投資不足 | レンジまで広告費を増やし自然検索売上の絶対額を伸ばす（率でなく絶対値・Skill 23） |
| AI自動運用ツールに任せきり | 予算上限設定＋キャンペーン別の消化額/ROAS | 高ROASキャンペーンに予算が回らず消化されていない | AI側の予算上限を外す／配分を手で組み替え（Skill 27） |

> 数値の科学的分解（寄与度・対市場シェア・ファネル段の特定）が要るときは ec-amazon-analytics に診断を依頼し、本Agentは「触り方」に責任を持つ。判断が割れたら3者議論プロトコルへ。

## Skills

### Skill 1: Ad Account Design（広告アカウント設計）
キャンペーン命名規則・属性別グループ分離・指名分離・キャンペーン階層設計。
- 命名規則ゼロのアカウントは集計不能 → 即再構築候補
- 指名検索KWは別キャンペーンに分離（CVR高いので攻めの設定維持）
- SP/SB/SDのプレフィックスをキャンペーン名に必ず入れる
- 商品別ポートフォリオで集計可能な状態を維持
- キャンペーン乱立はメンテ困難 → グループで分ける
> 詳細は [運用の参考資料](references/amazon-ads-fieldnotes.md)（該当する論点を検索して参照） を参照

### Skill 2: SP Manual Targeting Setup（SPマニュアル広告完全設定）
KW・ASIN・カテゴリの3種マニュアル広告を正しく設定する。
- KWターゲ：「部分一致」を必ず外す・フレーズ+完全一致のみ
- ASINターゲ：「拡張」は基本NG・完全一致のみ
- カテゴリターゲ：レビュー評価・価格帯で絞り込み（ブルーオーシャン狙い）
- Amazon推奨入札額は信用せず元のCPCベースで設定
- KWとASINは別グループに分離・カスタム入札で一括設定→後最適化
- ASIN抽出は Chrome 拡張ツール活用（オートデータない場合）
> 詳細は `references/manual-targeting-setup.md` を参照

### Skill 3: SB Ad Complete Setup（スポンサーブランド広告 完全設定）
3商品同属性ルール・カスタム画像必須・ヘッドラインコピー設計。
- 3商品同属性：違うカテゴリ混在は即否認リスク
- カスタム画像必須：商品画像流用ではCTR出ない
- ヘッドラインコピーは「ブランド訴求＋指名取りに行く」
- 指名検索KW中心に出向（CVR高い）
- SBV（SBビデオ）は別途設定・動画必須
> 詳細は [運用の参考資料](references/amazon-ads-fieldnotes.md)（該当する論点を検索して参照） を参照

### Skill 4: SD Ad Complete Setup（スポンサーディスプレイ広告 完全設定）
VCPM入札・4パターンリタゲ全設定・暴走防止。
- VCPM（Viewable CPM）入札の使い分け
- 4パターンリタゲ：自社購入者・自社閲覧者・競合閲覧者・カテゴリ閲覧者
- LookBack期間：30/60/90/365日の使い分け
- 設定直後は暴走しやすい → 1週間2-3回確認
- 暴走したら止めるのではなくCPC下げる
> 詳細は [運用の参考資料](references/amazon-ads-fieldnotes.md)（該当する論点を検索して参照） を参照

### Skill 5: Self-Product Retargeting（自社商品リタゲ）
自社商品ページから自社別商品への送客・指名KW分離。
- 全商品×全商品の総当たり設定

- 既存売れ筋のセッションを新商品/横展開商品へ流す
- 月のセッション5%でも吸い上げれば大きな新規導線になる

### Skill 6: Account Handover Diagnosis（新規アカウント引継ぎ診断）
新規受託・引継ぎ時の構造的診断。3段階アプローチで「素人運用サイン」を発見。
- A. ビジネス全体把握（売上推移2年・商品理解・シーズナリティ・バリエーション）
- B. ブランド戦略推測（公式LP/Amazon価格比較・セール参加履歴・Google広告/SEO）
- C. Amazon基本機能活用度（FBA・レビュー・Vine・クーポン・定期便・ストア・A+）
- D. 商品ページ品質（画像クオリティ・統一感・スマホ表示）
- E. SEO・KW（ブランド分析でメインKW特定・商品名挿入チェック）
- F. 広告構造（命名規則・商品別分散・オート/マニュアル・拡張使用・止め癖）
- G. ヒアリング項目化（推測で進めない・確認項目を必ず分離）
- H. 「素人運用サイン」スコアリング（改善余地＝伸び代として評価）
> 詳細は `references/account-handover-diagnosis.md` を参照

### Skill 7: Product Page Diagnosis（商品ページ診断）
売上を上げる前提条件としての商品ページ12項目チェック。
- メイン画像7枚の戦略的構成と品質
- 箇条書き5点のベネフィット訴求とKW挿入
- A+コンテンツのクオリティと使い回し有無
- レビュー数・評価・直近獲得速度
- ブランドストーリー・ブランドストア設定
- スマホ表示時の見え方
- 商品名・箇条書きへのメインKW挿入状況
数値や非公開の仕組みの断定は、原典と当該条件を確認するまで使用しない。顧客行動は取得できる実データで検証する。
- メイン画像はCVRにも効く（旧説「CTRはメイン/CVRはサブ」は更新中。メイン画像変更だけでCVR1.2倍の事例）。タイトルは変更で一時的に順位低下＋テスト回数に限りがあるので、メイン/サブ画像でクリエイティブテストを回す
- 白抜き画像の規制が緩和傾向：パッケージ同梱＋アテンションシール風で文字、化粧水のテクスチャ表現を商品背後に等（楽天的サムネ化）。緩和を見逃さず差別化（規制動向は platform-policy-check）
> 詳細は [運用の参考資料](references/amazon-ads-fieldnotes.md)（該当する論点を検索して参照） ＋ `references/amazon-ads-fieldnotes.md`（§9）を参照

### Skill 8: Monthly Maintenance（月次メンテナンス 理論+実演）
月2回ペースのメンテで最大インパクトを出す。
- 月2回（2週間に1回）が黄金頻度・データ統計的有意性確保
- 広告費降順で上から対応（インパクト最大化原則）
- 全体ROAS基準でキャンペーン判定
- ターゲ階層まで降りて1個1個判断
- 調整幅：通常20-30円・大胆50-60円
- 神KW判定＝全体平均ROASの倍以上 → 積極攻め
- CPC変更後30秒-1分でAmazon検索順位反映
- クライアント戦略前提（攻め型/守り型）と整合性必須
> 詳細は `references/monthly-maintenance.md` を参照

### Skill 9: KW Promotion Pipeline（KW昇格パイプライン）
オートターゲから始まる KW昇格の4段階。
- Step1：オートターゲで検索用語データ収集（過去65日最大）
- Step2：注文数のあるKWを抽出（オート平均ACOS基準で判定）
- Step3：フレーズ一致＋完全一致のマニュアル広告へ昇格
- Step4：高ROAS KWはCPC上げて検索順位攻略
- 並行：ブランド分析・Amazonサジェスト・競合ページ・検索クエリパフォーマンスでKW追加
> 詳細は [運用の参考資料](references/amazon-ads-fieldnotes.md)（該当する論点を検索して参照） を参照

### Skill 10: Big Sale Ad Operations（ビッグセール広告運用）

- 売上規模別の関わり方（張り付き vs コミュニケーション重視）

### Skill 11: CPC Emergency Response（CPC高騰応急処置）
CPC高騰時の3ステップ応急処置。

- Step2：ROAS悪いキャンペーンを一括変更（自社指名は除く）
- Step3：既にダウンのみでもROAS悪いものは個別CPC下げ
- 「アップとダウン」は最大100%倍まで取る攻め設定であることを理解

### Skill 16: Product Name SEO（商品名SEO最適化）
SEO最優先項目としての商品名設計。
- KW×ページ関連性が本質（販売件数だけでは不十分）
- 商品名が断トツ最優先（PC表示上から順原則）
- 文字数規約：200文字以内(2025-01-21〜)／2026-07-27以降スペース込み75文字以下(メディア除く・グローバル)。75超はAIが順次自動書き換え・個別通知なし。14日レビュー枠はブランド登録者のみ（未登録は書き換え後に修正）。書き換え検知運用＝売上上位ASINを週1目視＋変更前商品名を控えて突き合わせ ※確定は platform-policy-check で都度照合
- 75字に残すKWの定量基準：ブランド分析「上位の検索用語」で検索頻度ランク5桁台までを商品名に残す（3〜4桁台=ビッグ・5桁台=ミドル）。移行実務の全体は `references/title-highlight-migration-2026.md`
- 先頭5単語＝カノニカル。最重要KWを必ず先頭5語に置く。半角スペースで別ワード扱い（完全一致）
- 同一単語は最大2回まで（3回以上は禁止。冗長な反復は上限内でも避ける）／記号 ! $ ? _ { } ^ ¬ ¦ 不可・機種依存文字不可
- 弊社式：SEO語（検索頻度ランク上位）×CTRアテンション語×仕様 を役割分担で配置。SEO型KW＝検索を取る／CTR型語＝目を止める（レビュー高評価テーマを言語化）
- 順序：ブランド名→メインKW→アピール(CTR)→サブKW→仕様。※無名ブランドはメインKW先頭も可（SEO/カノニカル最大化）
- アテンション語は単独の属性名ではなく、原材料・産地・製法・香り・味わい・利便性などの確認済み事実から「選ぶ理由」が一息で伝わる短いフレーズにする（例：`カカオ香る チョコようかん`）。主観・販促表現は使わず、官能表現は商品仕様または官能確認で裏付ける
- 容量・入数・サイズ・型番は商品識別に必要な場合だけ商品名へ残し、ハイライトでは再掲しない
- CTR短句を作る前に、対象ASINのAmazon現行メイン画像を目視し、パッケージ表面・アテンション帯・シールの文言を転記する。Shopify、ブランドサイト、商品説明文だけで代用しない
- タイトルのCTR短句は、Amazon現行画像にある「選ぶ理由」のコピーを優先する。画像コピーを短縮・要約する場合も、元コピー・ASIN・確認日を追跡可能に記録する
- 累計販売数、受賞、No.1等は「Amazon画像に掲載されていること」と「主張を裏付ける元データが確認できたこと」を分離する。元データ未確認ならタイトル・ハイライトへ転用しない
- ブランド分析の検索頻度ランクや購入実績が未取得なら、KW優先順位を断定せず暫定案として明記する
- 薬機法・景表法考慮（効果系/症状名/部位名/糖質オフ等NG）
数値や非公開の仕組みの断定は、原典と当該条件を確認するまで使用しない。顧客行動は取得できる実データで検証する。
- KWは7〜10個に絞り1語あたりの関連性を高める（自然検索は詰め込むと関連性が分散しうる／広告では分散しない）。商品名は短く（文字数規約は上記＝platform-policy-check が正本）
> 商品名とハイライトの2026年実装手順は `references/product-title-highlights-2026.md`、広告面の補足は `references/amazon-ads-fieldnotes.md`（§8）を参照

### Skill 22: Product Highlights Design（商品のハイライト設計）

- 表示条件：商品名が75文字未満のときのみ表示。入力はセラセン「在庫→全在庫の管理→出品情報の編集」
- 完全な文ではなく、短い比較フレーズを半角カンマ区切りで4〜5個、1項目20文字前後並べる。確認済み事実が足りなければ無理に埋めない。区切り後のスペース有無は現行UI・実装手順で都度確認する

- 役割＝検索補完＋比較判断＋ひと目スキャン。CTRを高める「選ぶ理由」の短句は商品名に置き、ハイライトは素材・仕様・用途の短い比較タグに徹する

- 商品名とハイライトを同時に完成させ、変更前の順位・セッション・販売個数を記録して一度で反映する
- ハイライト作成前にも対象ASINのAmazon現行メイン画像を確認し、タイトルに採用済みの容量・本数・CTR短句を除外する。残った確認済みの素材・産地・仕様・用途を短句にする

### Skill 23: TACoS-Driven Budget Design（TACoS主導の予算設計・絶対値思想）
広告費は「自然検索売上の絶対値を上げる投資」。比率でなく絶対額で判断する。
- 3指標：ACoS＝広告費÷広告経由売上／ROAS＝その逆／TACoS＝広告費÷アカウント全体売上（自然検索込み）が最重要
- 商材別TACoSレンジ（現場体感）：化粧品30%前後／サプリ25〜30%／雑貨・トレーニング・中国OEM系7〜10%。伸び切った後はほぼ定数
- 「TACoSが下がればOK」ではない。適切レンジに収まっているかが本質
- TACoSが低すぎる＝広告を使わなさすぎ＝機会損失。レンジまで増やし自然検索売上の絶対額を伸ばす（TACoSが上がっても利益絶対額が増えれば成功）
- 「月商水準を上げる」こと自体が原価削減圧力（OEMロット発注）→ 最もレバレッジが効く
> 詳細は `references/amazon-ads-fieldnotes.md`（§3）を参照

### Skill 24: Ad-Type Budget Ratio（広告タイプ予算配分・黄金比率とフェーズ移行）
SP/SB/SDの黄金比率とフェーズ別ステップアップ。
- 黄金比率（DSP除く）：SP 7割／SB 1〜2割／SD 1〜2割（教科書的）
- フェーズ：月予算10〜30万・月商〜200万＝SPのみ（オート＋マニュアル）／CVR整備後にSB追加／月商500万前後でSD追加
- 予算配分ミスが最頻。商材相性あり（化粧品はSB動画/スポンサードTVがROAS良いことも）
- スポンサードTV・DSPは月商数千万超向け。500万以上でもDSPを安易に使わない（単体ROASが見えづらい・ラストクリック課金）。AMCでフルファネル分析
> 詳細は `references/amazon-ads-fieldnotes.md`（§4）を参照

### Skill 25: Brand Keyword Defense（指名キーワード防衛）
指名（ブランド）KWは守りで必須。競合奪取の機会損失を止める。
- 「指名で検索した客はどうせ買う」は誤解。競合が指名KWに出稿し流入を奪う
- 守りで入れないと機会損失が激しい（事例：指名KW追加だけで月商70万→200〜300万）
- リスティングと違いAmazonは指名でも競合が出稿でき、競合商品ページにも広告を出せる
- 初期設定の確実階層：第1層ブランドKW（指名・必須）→第2層商品ジャンルKW（完全一致から昇格）→第3層周辺/代替KW（余裕があれば最後）
> 詳細は `references/amazon-ads-fieldnotes.md`（§5）を参照

### Skill 26: Negative Keyword Ops（除外キーワード運用＝ACoS改善の最強手段）
ACoS改善の最強手段は除外KW。オートもマニュアルも週次で締める。
- オートは広く意図しないKWに出る（鮭茶漬け→鮭の切り身）。マニュアルの部分/フレーズ一致・カテゴリーターゲも意図しない面に出る
- オートもマニュアルも週次で除外設定（自社運用は週次でよい／プロは当日・翌日・毎日）
- 判断のクリック閾値：判断には20クリック以上。早期判断なら10クリックでCV有無。ACoS 50%超かつクリック10〜20以上なら即除外
- 例外：CVそのものを増やしたい初期フェーズは除外しすぎない（フェーズに合わせる）
> 詳細は `references/amazon-ads-fieldnotes.md`（§7）を参照。オート→マニュアル昇格は Skill 9 と一体運用

### Skill 27: AI Auto-Ops Diagnosis（AI自動運用の診断）
AI任せ運用は伸び代の塊。予算配分の偏りを暴く。
- AIの強み＝最短で60〜70点。弱み＝細かい予算配分・キャンペーン別最適化
- 典型事故：AI側で予算上限設定 → 高ROASキャンペーンに予算が回らず消化されない
- 診断：予算が消化されていない高ROASキャンペーンを真っ先に探す → 上限を外す/配分を組み替える
- 「初期設定のまま1〜2ヶ月放置」「メイン画像が白抜きのまま放置」も同様の伸び代サイン
> 詳細は `references/amazon-ads-fieldnotes.md`（§2）を参照。素人運用サインに「AI任せ」を追加

### Skill 28: Launch Review Bootstrap（レビュー初動設計・規約準拠）
レビューはCVRの命。ローンチ初動の10個を規約準拠で作る。

- OK：同梱チラシでフラットに依頼／公式レビューリクエスト機能（レビュー率約1%→3〜4%）／インフルエンサーに「ローンチ」とコンテンツ化して応援依頼
- NG：インセンティブ付与・星の指定（特典付与/ステマ規制違反）
> 詳細は `references/amazon-ads-fieldnotes.md`（§10）を参照。規約の確定は legal-check / platform-policy-check

## 「素人運用」の見抜き 5サイン（即診断ポイント）

```
1. キャンペーン命名規則ゼロ
   → 集計不能・属性別判断不能

2. オートターゲに広告費集中
   → 自分でコントロールできない領域に投資

3. ASIN拡張ターゲ使用
   → 類事商品に無制限拡散・効率悪化

4. 大きなKWを「悪いから止めた」
   → CPC下げて維持の選択肢を知らない

5. SD広告暴走→完全停止
   → 1回失敗で全停止・CPC調整できていない

6. AI自動運用ツールに任せきり／初期設定のまま放置
   → 高ROASキャンペーンに予算が回らず消化されない・メイン画像が白抜きのまま（Skill 27）
```

→ これらが見つかった引継ぎアカウントは「ガラ空き＝伸び代」と判断
