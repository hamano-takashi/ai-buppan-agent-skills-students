# コンセプト設計シート（CF案件の型・正本）

CF案件でコンセプトを決めるときは、毎回この型で埋める。埋まっていない欄があるまま構成案やコピーへ進まない。

正本のファイル: 利用者が用意した資料（未提供なら確認する）

このxmindは2枚組で、両方セットで価値がある。

- 1枚目「分析シート」= 空のテンプレート。以下に構造を写してある
- 2枚目「◯◯分析シート」= 同じ型を実案件で埋めた記入済み例。粒度の基準はこちらを見る

記入済み例は特定商材の情報を含むため、他案件の資料へ内容を持ち出さない。参照するのは埋め方の粒度だけ。

## 使い方

1. 型を丸ごとコピーして案件用のシートを作る
2. 上から順に埋める。埋まらない欄は空欄のままにせず「未取得」と書く。推測で埋めない
3. 「仕様」と「探し方」が埋まってから「構成案」へ進む。順番を飛ばすと、コンセプトが商品理解ではなく思いつきになる
4. 構成案のFVが決まった時点で、コンセプトが決まったと判断する

### 1. 仕様

- ベネフィット
- 損失回避

  - スタイル: 重量（梱包含む・本体のみ）／カラーバリエーション／デザイン／サイズ（製品サイズ・収納時サイズ）
  - パッケージ
- 付随機能
- BTRNUTTSの法則: 有益性／信頼性／緊急性／数字／独自性／話題性／意外性／物語性

### 8. 構成案

FV（ここが決まればコンセプトが決まったと見なす）

- コンセプト
- ベネフィットコピー
- 製品名（正式名称）
- プロジェクト概要（120文字以内）
- 特徴まとめ（各: タイトル10-15文字以内／本文30文字以内）
- 解決策（目指す理想の状況は？／何で解決するのか？）
- USP

以降の並び順:

よくある悩み → 特徴①の詳細 → 特徴②の詳細 → 特徴③の詳細 → リスクリバーサル → キャンペーン → 製品スペック（仕様） → 同梱物の紹介 → リターン一覧 → 開発ストーリー → メーカー紹介 → 実行者紹介 → よくある質問 → リスク&チャレンジ

### 9. ストーリー作成

先に箇条書きで要素を出してから文章にする。いきなり文章から書かない。

出す要素:

- 自分の紹介・経歴（商品と関わりがある場合）
- 開発の動機
- 直面した課題や困難
- どの位深い悩みを持っていたのか
- 支払った代償（試作やテストした回数など）
- 解決への覚悟（これを開発したら誰が助かるのか）
- 葛藤と緊張感（このまま続けても成功するのか、など）
- サプライズ（解決策とのふとした出会い）
- 感情的な反応（商品を試してみた時の感動）
- 受け手にとっての有効性（周りの人に試してもらった感想）
- わかりやすいメッセージ（誰に届けたいのか）
- ブランドとのつながり（ブランド名の由来など）
- ユーモア

そのうえでストーリーテリングの順に並べる。

日常の悩み → 解決策との出会い → 制作過程の挑戦 → 製品の何で悩みを解消したのか

## 記入済み例から読み取れる埋め方

- ターゲットイメージと市場所見は、プラットフォームのレビュー本文から顧客の要望を直接拾って書く。想像で書かない
- 市場の偏り（どの用途の需要が多く、どの用途が手薄か）まで書く。空いている用途がPODの入口になる
- 話題になっている方式・規格があれば、レビュー評判とセットで記録する
